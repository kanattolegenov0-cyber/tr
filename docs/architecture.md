# Архитектура и этапы

React → FastAPI → адаптер market_data → проверка OHLCV → indicators → feature_engineering → ml_models → signal_engine → ai_analyst.

Этап 1: публичный ccxt/CSV, BTC (также ETH/SOL), четыре интервала, свечи/объём, индикаторы, Logistic Regression, отдельная сигмоидальная калибровка, отложенная оценка, HOLD при устаревании или неподтверждённом качестве. Объяснения шаблонные, без LLM и выдуманных чисел.

Временное разбиение 60/20/20. На границах исключена одна обучающая цель, поскольку она использует следующую свечу. Скейлер обучен только на train. Финальный test не участвует в подборе параметров или калибровке. Проверка baseline — минимальный исследовательский фильтр, не статистическое доказательство надёжности. Версия алгоритма передаётся в ответе; сохранение обученных артефактов пока не реализовано.

Этап 2: walk-forward/TimeSeriesSplit, Random Forest/XGBoost, версии артефактов, backtesting с исполнением на следующем открытии, комиссиями/проскальзыванием; SQLite/SQLAlchemy, риск-лимиты и виртуальный портфель 1000 USDT. Сначала тесты причинности, исполнения и балансов.

Этап 3: Academy, чат с подтверждёнными данными, APScheduler, Telegram с дедупликацией. Секреты локально в .env, без логирования и коммитов.

Этап 4: Docker Compose, расширенные интеграционные тесты и UI. Модули risk_management, backtesting, paper_trading и notifications добавляются с реализацией, пустые заглушки не выдают себя за функции.

Нет реальных сделок, шортинга и плеча. Прогноз относится к close следующей свечи, не к гарантированной исполнимой доходности. Исторический CSV маркируется как непроверенный источник; устаревшие данные блокируют сигнал. Нулевые объёмы могут оставлять неопределённые признаки и блокировать модель.
